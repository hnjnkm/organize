# organize

기존 Pinterest 디자인 리서치 라이브러리의 2026-11-05 스냅샷에서 추출한 개발 버전입니다. 화면 구조, CSS 선언 순서, 한영 사전, 검색/필터/모달/영상 로직을 유지했습니다. 원본 보드: https://kr.pinterest.com/hnjnkm_/research-gui/

## 실행

Node.js 24 이상과 Chrome을 사용합니다. 화면 실행에는 빌드가 필요 없습니다. 수집기는 Playwright를 사용하며 `npm ci`로 설치합니다.

```sh
npm run import -- "/path/to/organize-current-snapshot.html"
npm start
```

현재 클라우드 작업 환경에는 자료를 이미 가져왔으므로 `npm start`만 실행합니다. Chrome에서 `http://127.0.0.1:4318`을 엽니다. Windows에서는 `START.cmd`도 사용할 수 있습니다. 서버는 루프백에만 바인딩합니다. 다른 포트는 `PORT` 환경변수로 지정합니다.

## 파일과 데이터 보존

- `public/index.html`: 기존 화면 구조
- `public/styles.css`: 기존 스타일과 내장 Pretendard 폰트·라이선스
- `public/app.js`: 기존 UI, 분류, 편집, 내장 데이터 대신 JSON 로딩
- `public/menus.js`: 기존 커스텀 선택 메뉴
- `server.cjs`: 개발용 정적 파일 서버 (기존 수집 서버를 복원한 것은 아닙니다)
- `data/snapshot.json`: 71개 핀, 이미지와 24개 영상 및 분류 메타데이터. Git에서 제외합니다.

Git에는 코드만 저장합니다. 다른 컴퓨터에서는 원본 HTML 또는 `data/snapshot.json`을 별도로 복사해야 합니다. 가져오기는 기존 파일을 덮어쓰지 않습니다. 새 자료로 교체하기 전 기존 데이터와 화면의 JSON 백업을 별도로 보관하세요. 원본 HTML은 변경하지 않고 별도로 보존하세요.

편집은 원본처럼 해당 브라우저/주소의 localStorage(`form-snapshot-edits`)에 저장됩니다. 브라우저나 포트가 바뀌면 편집 내용이 자동 이동하지 않습니다. JSON 백업 버튼은 편집한 자료와 내장 미디어를 내보냅니다. JSON 백업 복원 UI는 아직 없습니다. 중요한 변경 후 백업을 보관하세요.

## 현재 범위

스냅샷에 실제 들어 있던 기능을 이어받았습니다. 기존 서버는 포함되지 않았습니다. 새 Windows 수동 수집기는 아래 절차로 사용하며, 주기적 자동 동기화와 서버의 보관본 ZIP 생성은 제공하지 않습니다. 원래 스냅샷의 관련 안내/버튼 동작을 유지합니다. 보드 주소만으로 이전 서버·로그인 세션·브라우저 편집을 복원할 수 없습니다. 현재 구조는 1만 개 자료를 위한 최적화를 구현한 상태가 아닙니다.

## 검증

`npm test`로 자료 구조 및 개발 서버의 응답·접근 제한을 확인합니다. 자료 파일이 없으면 자료 검증은 건너뜁니다. UI 수정 시 Chrome에서 카드 이미지, 영상, 검색, 언어 전환, 모달 저장 및 모바일 레이아웃을 확인하세요.


## Windows에서 새 핀 수동 동기화

필수: Node.js 24+, Google Chrome, Git for Windows. 저장소 코드를 다운로드/복제한 PC에서 실행하세요. 로그인 세션과 개인 자료는 Git에서 제외됩니다.

1. `START.cmd`를 실행합니다. 최초 실행에는 의존성과 기존 게시 자료를 준비한 뒤 로컬 화면을 자동으로 엽니다. 열린 명령 창은 앱이 실행되는 동안 유지하세요.
2. organize 화면의 **Chrome 로그인**을 누릅니다. 전용 Chrome 창에서 Pinterest에 로그인하고 대상 보드를 엽니다.
3. organize 화면으로 돌아와 **지금 동기화**를 누릅니다. 명령 창에 Enter를 입력할 필요가 없습니다. 수집 상태가 화면에 표시됩니다.
4. 완료 후 새 카드를 확인하고 **사이트 반영**을 누르면 GitHub에 업로드합니다. GitHub 쓰기 권한이 있는 계정으로 Git 인증이 필요하며, 최초 인증 때 Git Credential Manager의 안내를 따르세요.
5. GitHub Pages 배포가 끝나면 공개 사이트를 새로고침합니다.

이 버튼은 PC에서 실행한 로컬 앱에 표시됩니다. GitHub 공개 사이트가 PC의 Chrome을 직접 조작하는 구조는 아닙니다. `SYNC.cmd`와 `PUBLISH.cmd`는 수동 실행용 보조 도구로 남아 있지만 위 흐름에서는 필요 없습니다.

Chrome은 전용 `private/pinterest-chrome`에 로그인 상태를 저장합니다. 이 폴더를 공유하지 마세요. 중단 후 동기화 잠금 오류가 나면 수집기 프로세스가 종료됐는지 먼저 확인한 후 `private/sync.lock`만 삭제합니다.

### 수집 범위와 검증 한계

- 보드를 스크롤해 실제 표시된 핀을 확인합니다. 최대 60회 스크롤하며, 6회 연속 새 핀이 없으면 종료합니다. 전체 보드 수집을 보장하지 않으며 실행 로그에 확인한 개수를 표시합니다.
- 상세 페이지의 제목·설명·이미지 및 직접 MP4 주소를 수집합니다. 제목 번역/자동 분류/색상 분석/HLS 영상 변환은 아직 없습니다. 영상 주소가 노출되지 않으면 이미지와 원본 링크만 보존합니다.
- 새 핀은 분류 검토가 필요한 상태로 추가됩니다. 이전의 수동 편집을 추정하거나 덮어쓰지 않습니다.
- 사이트에서 바꾼 메모 등은 계속 브라우저 localStorage에 있습니다. 수집/게시가 이것을 Git에 자동 저장하지 않습니다. 다른 PC로 옮기기 전 JSON 백업을 보관하세요.
- 게시는 원격 최신 gh-pages를 먼저 받아 **새 ID만 병합**합니다. 원격에 이미 있는 핀과 미디어는 보존합니다. 동시 게시 충돌은 강제 덮어쓰지 않고 push가 실패합니다. 재실행하면 최신 자료에 다시 병합합니다.
- 현재 클라우드에서는 Pinterest가 HTTP 403을 반환해 실제 로그인 수집을 끝까지 검증하지 못했습니다. 병합/중복 방지/기존 편집 보존 테스트를 통과한 초기 버전이며, Windows 첫 실행 결과로 실제 Pinterest 구조 호환성을 확인해야 합니다.
